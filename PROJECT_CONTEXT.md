# Fantasy AI — Project Context

_Last updated: 2 August 2026_

This file summarizes the current state of the **Fantasy AI** project so work can continue in a new ChatGPT conversation without reconstructing the full history.

## 1. Project goal

Fantasy AI is a web app for fantasy-football auctions. Current functions:

- browse, search, filter and sort players;
- open player details and compare two players;
- register and authenticate users;
- create, resume and delete multiple auction sessions;
- register and remove auction purchases;
- isolate each user's auctions;
- persist authentication across reloads.

Preferred working method:

- one step at a time;
- exact file paths and replacement blocks;
- test before build;
- build before commit;
- clear comments in important code blocks.

## 7. Same-origin backend proxy

Browser architecture:

```text
Browser
  ↓
Vercel /api/backend/*
  ↓
Render FastAPI
```

Frontend API base:

```ts
export const API_URL = "/api/backend";
```

Proxy route:

```text
frontend/app/api/backend/[...path]/route.ts
```

The proxy:

- uses the Node.js runtime;
- is dynamic;
- forwards path, query, headers and body;
- forwards `Set-Cookie`;
- reads server-only `BACKEND_API_URL`;
- checks `Origin` for unsafe methods;
- uses `no-store`;
- supports GET, POST, PUT, PATCH, DELETE and OPTIONS.

Expected build route:

```text
ƒ /api/backend/[...path]
```

Browser requests should use:

```text
/api/backend/auth/login
/api/backend/auth/me
/api/backend/auction-sessions
```

Do not reintroduce direct browser calls to Render.

## 10. Auction backend routes

Important routes:

```text
GET    /auction-sessions
POST   /auction-sessions
GET    /auction-sessions/{session_id}
PATCH  /auction-sessions/{session_id}
DELETE /auction-sessions/{session_id}
```

There are also protected routes for registering and deleting purchases.

`PATCH /auction-sessions/{session_id}` supports:

- renaming a session through `leagueName`;
- changing its status between `ACTIVE` and `COMPLETED`;
- preserving configuration, teams and purchases.

`GET /auction-sessions` returns only the current user's sessions.

## 11. Multiple auction sessions

Multiple auctions per account are supported.

Behavior:

- each new auction gets a new database UUID;
- `/my-auctions` lists all auctions owned by the current user;
- `localStorage` stores only the UUID of the selected auction;
- creating a new auction removes only the selected UUID from `localStorage`;
- previous auctions remain in PostgreSQL;
- `Riprendi asta` selects a session and opens `/auction`;
- completed auctions remain available in read-only mode and can be reopened;
- sessions can be renamed from `/my-auctions`;
- `Elimina` deletes the chosen auction from the backend;
- deleting the selected auction also clears its local UUID.

Storage constants:

```text
frontend/lib/auction-storage.ts
```

```ts
AUCTION_SESSION_ID_KEY =
  "fantasy-ai-auction-session-id-v1";

LEGACY_AUCTION_STORAGE_KEY =
  "fantasy-ai-auction-session-v1";
```

`/auction`:

- waits for authentication;
- restores only the selected auction;
- clears an inaccessible or missing UUID after `404`;
- reports expired login after `401`;
- shows a new-auction form when no UUID is selected.

`/my-auctions`:

- lists saved sessions;
- resumes a selected session;
- deletes sessions after confirmation;
- creates an additional independent session;
- uses the global circular transition.

Current dashboard layout:

- `Nuova asta` is a dashed card inside the same grid as saved auctions;
- saved auctions are cards with summary values;
- each saved card has `Riprendi asta` and `Elimina`;
- each saved card also supports inline renaming;
- completed cards use `Visualizza asta` and remain read-only until reopened;
- the old wide horizontal new-session banner was removed.

Grid layout:

```tsx
grid gap-5 md:grid-cols-2 xl:grid-cols-3
```

The new-auction card appears before `sessions.map(...)`.
